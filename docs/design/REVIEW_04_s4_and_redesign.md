## 1. S4 Proposal — **REJECTED as shipped** (the screen's core idea is approved; its current state is not)

The face-chip concept works — the tray is genuinely good. But the screen fails on the two things that define it: **the user never reaches it**, and **the photo shows the user nothing**.

- **F1 (BLOCKER) — S4 is unreachable in the shipped flow.** Nothing in the app navigates to it. `HomeController` still routes pick → consent → `Routes.processing` (the old single-call loop); `ProcessingApi.detectPersons` has **no caller anywhere in feature code**. S4 exists as a routed screen plus golden captures only. That is dead UI by the project's own rule, and it means Review 02's gap **G1 is not closed**: confirm-before-removal — the product's defining promise — still does not happen in the real flow. *Fix:* wire the golden path pick → (consent) → analysing state → S4 → confirm → S6 carrying the keeper ids (the plumbing already exists: `ProposalArgs`, `ProcessingArgs.keepIds`). On detect failure, fall back to the existing single-call processing — never a dead end, never a silent mock. The `proposalAnalyzing` string ("Analyzing photo…") already exists for the analysing state and is currently unused.
- **F2 (BLOCKER) — the canvas overlays never draw with real data.** `_OverlayPainter` compares full-resolution **pixel** boxes against the **dp** photo band and draws only if the box happens to fit inside it (`bx2 <= size.width && by2 <= size.height`). With real /detect output (boxes in the hundreds–thousands of px), nothing ever paints. Verified visually: captures fed with real-shaped boxes on the cafe photo show **zero outlines on the photo**, in light and dark. The painter even documents the gap ("we approximate… chips are the primary tap targets") — an approximation that silently evaluates to *never* is a fake surface, and the canvas is likewise not tappable despite the view's doc comment claiming box taps toggle. What remains is chip-only identification, which fails exactly where it matters: Person 3's chip crop is a dark, partial figure that cannot be confidently matched to a place in the photo. *Fix:* scale boxes into band coordinates (PhotoSurface already resolves the image's intrinsic size — the geometry exists in the building), paint outlines + low-alpha fills as designed, hit-test taps in photo coordinates, and give each instance TalkBack semantics per direction R2 ("Person 3, marked to remove. Double-tap to keep.").
- **F3 (MAJOR) — dead primary button in two reachable states.** Keep-all and no-people both render a **disabled** button labelled "Keep all (nobody to remove)" (both captured). A disabled button whose label names an action is dead UI, and both states have a specified correct behaviour the build ignores: keep-all completes the job locally with the original photo, uncharged (requirements §7.3); the no-people state needs "Choose a different photo" as its action plus a plain exit (direction §4-S4). *Fix both states' actions; a proposal screen must never strand the user.*
- **F4 (MAJOR) — no live status sentence.** The one-line summary the direction requires ("3 people will be removed · 1 person protected", §11.2C formats) is absent; state exists only per-chip, and the tray scrolls horizontally — in the captures, the 4th person's chip is cut off at the edge with nothing telling the user a 4th person exists. The button's remove-count helps but does not state who is protected. *Fix:* the live sentence above the tray, updating on every toggle.
- **F5 (MINOR) — the low-confidence band is unused.** Detections carry scores end-to-end (worker → model), and requirements §6.4 define the 0.35–0.55 "not sure" band; the UI never reads `score`. *Fix:* a neutral "Not sure" chip state for the band plus the approved sentence ("We're not sure about one person — tap them to decide.").
- **F6 (MINOR) — overlap banner size.** The warning works (logic and copy verified — it fires correctly when a removal box intersects the keeper's, with the §11.2C touch-up wording), but it renders at caption size. It is a quality warning users act on: raise to `bodySm`.

**Approved inside S4, explicitly:** the chip tray itself — real crops, keeper/removal rings with check/× badges, **word** state pills ("Subject (keep)" / "Remove") under each "Person N" — is the right identification surface and satisfies the redundancy requirement at the per-person level; the title ("Review people to remove") is plain and factual; the confirm label names outcome + live count ("Remove 3 people"); dark mode is fully legible. When F1–F4 land, this screen can be the product's best screen. Today it is a well-built room with no door and no windows.

## 3. The redesign screens (Home / S6 / S7 / S10 + keeper sheet)

- **Home (redesigned) — APPROVE.** The inverted hierarchy (Pick → saves card → teaching line → demo card) puts the action and the proof first, and the demo card is the strongest single addition in the redesign: a *real* pipeline pair (owner-selected cafe photo, verified output), Original/Cleaned labels, drag divider, and the honest caption "Real app output". The with-history state is equally composed (history first row with "Cleaned" badges, demo below). Two records, not objections: (a) the saves meter is now a **card** — this supersedes my Review-02-era "not a card" rule; the redesign's version is tidy and the meter stays truthful, so the supersession is recorded (amendment D3) rather than fought; (b) the first-run harness capture shows the demo card blank — a capture-settle artifact (the card renders correctly in the 1.30 and with-history captures and on device); the harness note is in §5.
- **S6 (darkroom) — APPROVE.** The always-dark studio canvas ends the surround argument by making the wait a place, not a letterbox. **F2 (Review 02) re-checked against reality, as briefed:** the live copy — "High-resolution processing takes ~2 minutes. Keep the app open while we work." — still matches the CPU worker's truth, and the progress bar remains honest (determinate for upload bytes only). The revert condition is unchanged and now precisely scoped: when the Phase 2 gateway + resumable jobs land, "~2 minutes / keep the app open" comes out in the same change.
- **S7 (redesigned) — APPROVE with F7.** I specifically audited the disclosure reorganization against the requirements: the summary line, the meter-before-tap line, the location line, and the verbatim §11.2B disclosure with Report are **all still visible without any interaction** — the "capsule" did not bury a mandatory disclosure, so it stands. Save is dominant, the keeper link is centred with its swap icon, and the **wrong-keeper sheet is excellent**: visual crops, "Person 1 — protected" / "Person 2 — will be removed" in words, "Keep this person instead", and the factual footer "Re-running is free — it never uses a save." That sheet is the standard S4's tray should feel like.
- **S10 (redesigned) — APPROVE with F8 + F9.** The grouped-card layout is cleaner than the flat list and the facts survived (reset date present, provider from config, both privacy rows). **F9 (REQUIRED, copy):** the second group's header reads **"Before your photo is uploaded"** — that is the consent sheet's title, not a settings section; the redesign's own notes name this group "Processing & Privacy". A wrong header on the privacy group is exactly the kind of copy slip that erodes the trust this screen exists to state. *Fix the header string.*

## 4. Direction reconciliation (owner-adopted redesign vs DESIGN_DIRECTION)

Recorded so the documents stop contradicting each other; the owner's adoption of the audit is the authority for each supersession:

- **D1 — Palette.** The redesign tokens (cobalt `#2563EB`/`#60A5FA`, obsidian `#0B0D11`, porcelain `#F8F9FA`, emerald/crimson overlays at 60%) are the current token truth (REDESIGN_NOTES §2). My pre-audit assessment of the cobalt swap is superseded by the owner's decision.
- **D2 — Photo surround.** A3's "one surround rule" principle stands and is now satisfied differently: S3/S6 use the always-dark darkroom canvas; S7 keeps the photo band on the theme canvas with band-pinned chrome. The per-screen inconsistency A3 was written against does not exist in the redesign.
- **D3 — Home.** Action-first hierarchy, saves as a card, and the interactive demo card (real pipeline output only, honestly captioned) are the approved S1, superseding the Review 02 layout details where they conflict.
- **D4 — Consent format.** Structured trust cards are approved **conditional on fact-completeness** against §11.2A, verified in this review; any future copy edit re-triggers the fact check, not a format debate.
- **D5 — S4 identification.** The face-chip tray is the primary identification surface (approved). The on-photo boxes remain **required** — they are the photo-space half of the redundant-encoding rule (R2) — specified as outlines + low-alpha fills as designed in the build's painter intent (see F2 for its repair).
- **D6 — S7 composition.** Dominant Save + secondary Share, status-icon summary, centred keeper link: approved as built, with the standing rule that §11.2B's disclosure stays visible without interaction.
